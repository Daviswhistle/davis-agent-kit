# 작업자

[공통 규약](README.md)을 먼저 읽는다. 맡은 TASK의 구현·검증과 사실에 맞는 결과 보고를 책임진다.

## 시작할 때

- 위임받은 경우 지정 TASK 판, 프로젝트 지침, 필요한 인계 자료를 읽고 접수를 회신한다. 운영자가 직접 맡긴 같은 세션의 작은 일은 필요한 기록을 기존 보드·인계 문서에 남긴다.
- 실제 실행 기기·기준 코드·작업 경로·기존 변경을 확인한다. 다른 담당의 변경을 되돌리지 않는다. 담당과 보고 대상이 없거나 모호하면 맡긴 쪽에 확인한다.

## 수행

- 승인된 목적과 범위에서 구현과 필요한 검증을 끝낸다. 작은 실행 선택마다 재승인을 요구하지 않는다.
- 범위 확대나 추가 권한이 필요하면 구체적인 이유와 필요한 행동을 맡긴 쪽에 보고한다. 의존하지 않는 작업은 계속한다.
- 기준 코드나 입력이 바뀌면 영향받는 검증을 다시 수행한다. 실패·중단·미실행·미확인을 성공으로 기록하지 않는다.
- 별도 지시 없는 하위 작업자 생성이나 다른 프로젝트 착수로 과제 범위를 넓히지 않는다.

## 결과 전달

- 위임 과제의 REPORT 첫머리에 결론·영향·남은 일을 평문 3~5줄로 쓴다. 수행한 TASK 판과 코드 판, 변경 범위, 검증 명령·결과, 한계를 남긴다. 같은 세션의 작은 일은 기존 인계 기록에 필요한 내용만 쓴다.
- 구현 완료는 팀장 수용·운영 배포 완료와 구분한다. 커밋·원격 반영·배포 여부는 실제 수행 근거대로 쓴다.
- 결과 위치와 요약을 맡긴 세션에 전달한다. 공유되지 않은 로컬 경로만으로 다른 기기에서 결과를 읽을 수 있다고 보고하지 않는다.
- 장시간 대기나 세션 교대가 필요하면 이미 한 일, 막힌 이유, 다음 행동과 재현 위치를 문서에 남긴다.
