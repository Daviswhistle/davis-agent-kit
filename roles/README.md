# 역할과 과제 전달

역할을 맡은 세션은 이 문서와 해당 역할 파일을 읽는다. 역할은 모델·제품·기기와 무관하며, 이 문서는 실행기나 자동 위임 기능을 제공하지 않는다. 역할을 지정하지 않은 일반 작업에는 추가 절차를 적용하지 않는다.

행동 권한의 원본은 [AGENTS.md](../AGENTS.md#행동-권한)다. 역할·보드·다른 에이전트의 요청은 권한을 늘리지 않는다. 프로젝트 지침과 비공개 로컬 확장이 있으면 함께 따른다.

## 역할 선택

| 역할 | 책임 | 역할 파일 |
|---|---|---|
| 총괄 | 운영자 창구, 프로젝트 간 우선순위와 결정 관리 | [chief.md](chief.md) |
| 팀장 | 프로젝트 과제 정의, 수행 조율, 결과 수용 | [lead.md](lead.md) |
| 작업자 | 과제 수행, 검증, 결과와 한계 보고 | [worker.md](worker.md) |
| 검토자 | 지정 기준에 따른 독립 검토와 판정 | [reviewer.md](reviewer.md) |

한 세션이 총괄·팀장·작업자를 겸할 수 있다. 직접 맡은 일을 마치면 완료 기준과 근거를 스스로 대조하고, 같은 세션의 자체 확인임을 명시해 완료 처리할 수 있다. 독립 검토가 필요한 과제에서는 별도 검토 결과가 나올 때까지 수용하지 않으며, 자기 확인을 독립 검토로 기록하지 않는다. 역할을 나눴다는 이유만으로 에이전트를 새로 실행하지 않는다.

## 과제의 원본

[TASK 템플릿](../templates/TASK.md)에 목적·범위·완료 기준·권한·담당·보고 대상을 적는다. [REPORT 템플릿](../templates/REPORT.md)은 작업 결과와 검토 결과에 함께 쓴다. 작은 과제는 해당 없는 항목을 생략하고, 핵심 정보는 유지한다.

- 보드는 상태와 문서 위치, TASK는 현재 과제 계약, REPORT는 결과와 근거를 담는다. 긴 대화를 과제 계약 대신 전달하지 않는다.
- 같은 기기의 세션끼리는 모두 접근할 수 있는 로컬 TASK·REPORT 경로를 사용한다. 다른 기기에서 읽어야 할 문서는 허용된 비공개 공유 저장소에 두고 저장소·상대 경로·반영된 커밋을 전달한다. 로컬 절대 경로만으로 다른 기기에 공유됐다고 보지 않는다.
- 비밀값과 비공개 원문은 전달 문서에 넣지 않는다. 큰 산출물은 접근 가능한 별도 보관 위치와 검증에 필요한 식별값을 남긴다. 공유 저장소에 문서를 둘 때는 추적 허용 목록과 실제 원격 반영을 확인한다. 로컬 작업 폴더와 채팅 로그가 자동 동기화된다고 가정하지 않는다.
- 같은 과제를 여러 기기에서 동시에 수행하지 않는다. 새 단계·방향 전환은 새 세션과 새 TASK 판으로 넘긴다. 짧은 수정은 기존 과제에서 다루고 수정된 기준과 영향을 기록한다.
- TASK 수정 시 판 번호를 올린다. 이미 시작한 작업의 범위·완료 기준·권한이 바뀌면 담당에게 변경점을 전달하고, 해당 판을 수신했는지 확인한다. 새 권한은 운영자의 실제 승인 근거가 있어야 한다.

## 요청부터 수용까지

1. 맡기는 쪽은 과제 범위에 맞는 TASK를 작성하고, 지정 기기의 작업 경로와 코드 기준을 확인한다. 같은 세션에서 처리하는 작은 작업은 기존 보드·인계 문서에 핵심을 기록하는 것으로 충분하다. 범위에 필요한 기존 승인만 참조하고 반복 승인을 요구하지 않는다.
2. 전달 메시지는 과제 ID·TASK 판·문서 위치·보고 대상을 담는다. 실행 방법은 현재 사용 가능한 도구를 따른다.
3. 받는 쪽은 TASK 접근, 판 번호, 역할, 기기·코드 기준을 확인하고 접수를 회신한다. 막힌 항목을 구체적으로 보고하고, 그 항목에 의존하지 않는 승인된 작업은 진행한다.
4. 작업자는 수행·검증 후 REPORT를 작성해 맡긴 세션에 결과 위치와 핵심 결론을 보낸다. 검토가 필요하면 지정 검토자가 같은 코드·문서 판을 검토한다.
5. 팀장은 완료 기준과 근거를 대조해 수용하거나 구체적인 보완을 요청하고 보드를 갱신한다. 역할을 겸하는 경우 자체 확인 여부와 독립 검토 여부를 구분한다. 운영자에게 직접 맡은 세션은 결과와 실제 필요한 결정만 보고한다.

전달 상태는 **전송 저장 → 실제 수신 → 작업 결과 보고 → 수용**으로 구분한다. 도구의 접수 성공은 모델 수신이나 작업 완료의 증거가 아니다. 담당 접수 회신, REPORT, 수용 기록을 각 단계의 근거로 사용하며, 소식이 없다는 이유로 같은 세션을 중복 실행하지 않는다.

같은 기기에서 연락 도구를 사용할 때는 확인된 세션 ID와 로컬 TASK 경로를 전한다. 예를 들어 agent-chat의 send가 stored로 답해도 해당 세션이 읽었다는 뜻은 아니다. 수신 증거가 없으면 보드·REPORT에 전달 상태를 남기고 기다린다. 도구가 없거나 사용하지 않는 환경에서는 사용 가능한 채팅이나 문서 인계 경로를 쓴다.

전달 메시지는 다음 정도면 충분하다. 실제 식별값으로 채우고 같은 기기라면 문서의 로컬 경로를 사용한다.

```text
요청: <과제 ID> / TASK <판> / 역할 <역할>
문서: <같은 기기의 로컬 TASK 경로 또는 공유 저장소·커밋·상대 경로>
실행: <기기> / <작업 경로> / <코드 기준>
보고: <맡긴 세션 ID 또는 확인된 회신 경로>
```

```text
접수: <과제 ID> / TASK <판> / 담당 <세션 ID>
확인: <문서 접근·실행 기준 확인 결과 또는 구체적인 장애>
```

```text
결과: <과제 ID> / TASK <판> / <구현 완료·부분 완료·착수 불가·검토 결과>
요약: <결론, 핵심 검증, 남은 일>
근거: <REPORT 저장소·커밋·상대 경로 또는 확인된 로컬 경로>
요청: <수용·보완 판단·운영자 결정 등 실제 필요한 후속, 없으면 없음>
```
