# Writing Quality

문체를 문장 표면의 습관으로 복제하지 말고, 무엇을 남기고 어떤 순서로 보여줄지 판단한 결과로 재현하라. 독자가 대상을 더 정확히 이해하고 바로 판단하거나 행동할 수 있는 글을 완성하라.

## 호출 경계와 우선순위

원고가 주요 산출물이거나, 장문·반복 발행·오독 비용이 큰 근거 기반 답변에서 별도 설계와 퇴고가 실질적으로 도움이 될 때 사용한다. 문장 형식이거나 출처를 쓴다는 이유만으로 호출하지 않는다.

사용자의 목적·형식·길이·원문 보존 요구, 사실과 논리, 독자와 사용 환경, 문체 순으로 판단한다. 소프트웨어 변경이 중심이면 `software-engineering`이 작업과 검증을 소유한다. 게시형 HTML에서도 이 스킬은 원고와 정보 구조만 맡고 렌더링·코드 검증은 분리한다.

## 핵심 기준

- 중심 질문에 답하고 필요한 인과 단계와 경계 조건을 설명한다. 사실·추론·가정·미확인을 구분한다.
- 추상 강조보다 확인된 사실·숫자·장면·과정을 우선한다. 핵심 답은 초반에 밝히되 서사나 관계 민감 메시지에는 필요한 도입을 허용한다.
- 문단마다 역할을 맡기고 논리를 진전시킨다. 짧음보다 밀도를 우선하되 이해와 검증에 필요한 설명은 남긴다.
- 한국어와 영어 각각에 자연스러운 문장을 쓴다. 전문용어·원어 병기·비유·대조는 정밀도나 이해를 실제로 높일 때만 쓴다.
- 제목은 본문이 입증한 내용과 근거의 강도를 따른다. 상투적 도입·결론·추상 강조를 반복하지 않는다.
- 편집에서는 고유한 표현과 강한 문장을 보존한다. 국소 수정으로 해결되면 전체를 다시 쓰지 않되, 구조가 이해를 방해하면 재구성한다.
- 결말은 도입을 반복하지 말고 판단·불확실성·관찰 지표·행동 요청 또는 압축된 명제로 닫는다.

## 필요한 자료만 선택

경로는 이 `SKILL.md`를 기준으로 해석한다. 짧은 메시지나 한두 문장 교정에는 작업표·분리 검수를 만들지 않는다. 비사소한 원고의 목적·독자·장르·완료 조건은 확인된 맥락으로 정하고, 아래에서 실제 필요한 자료만 읽는다.

| 작업의 필요 | 참조 |
|---|---|
| 장르에 맞는 구조 설계 | `references/genre-playbooks.md`의 해당 플레이북 |
| 장문·반복 조사 에세이에서 중복, 시간 관계, 주장별 근거 또는 분리 검수를 관리할 실익이 큼 | `references/evidence-backed-research-essay.md`와 그 안의 사실 검수·출력 언어 편집 경로 |
| 관계 민감한 자발적 협조 요청 | `references/recipient-centered-persuasion.md` |
| 게시형 HTML/CSS 분석 아티클 | `references/publishable-html-article.md` |
| 상세 품질 평가 또는 독자 중심 정보 설계 사례가 필요함 | `references/review-rubric.md` 또는 `references/reader-first-information-design-examples.md` |

의무·평가·징계·안전 지시를 호의적 조언처럼 꾸미지 않는다. 조사 에세이의 전문 절차를 일반 질의응답이나 짧은 수정에 적용하지 않는다.

## 검수와 전달

초안에서 질문에 대한 답, 사실·수치·날짜·비교축·인과 강도, 빠진 논리, 중복, 불명확한 지시어와 용어를 확인한다. 조사 과정의 URL·도구 표식·JSON·내부 메모가 독자용 본문에 새지 않도록 한다. 사용자가 요구한 출처·링크는 유지한다.

사실 오류·논리 오류·불명확성·리듬 문제·취향을 구분한다. 발견한 실패 유형은 관련 범위에서 함께 고치되, 한 번의 수정 때문에 영구 규칙·테스트·평가 세트를 자동으로 늘리지 않는다. 독립 검수가 불가능하면 self-review를 독립 검수로 표현하지 않는다.

완성 원고 요청에는 산출물을, 피드백·검수 요청에는 중요한 문제를 먼저 제공한다. 명백한 오류가 없는 최종 확정 원고에 추가 교정을 강요하지 않는다.
